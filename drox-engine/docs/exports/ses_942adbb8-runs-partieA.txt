## ✅ Problème corrigé !

### 🔍 Cause identifiée

Il y avait un **conflit entre les animations CSS et framer-motion** dans le fichier `globals.css`. Les classes `.title-bio` (titre "Drox IDE") et `.text-deep` (sous-titre) appliquaient une animation CSS `focus-deep` qui démarre avec :

```css
@keyframes focus-deep {
  from { filter: blur(4px); opacity: 0; }
  to   { filter: blur(0); opacity: 1; }
}
```

En même temps, le composant `home-content.tsx` utilisait **framer-motion** pour animer exactement les mêmes propriétés (`opacity`, `filter: blur()`) sur ces éléments. L'animation CSS écrasait les valeurs gérées par JS, empêchant le texte de s'afficher correctement dans la section Hero.

### 🔧 Correction appliquée

Dans `app-kdds-main/src/app/globals.css` :

| Classe | Avant | Après |
|--------|-------|-------|
| `.title-bio` | `animation: pulse-glow ..., focus-deep 1.2s ease-out forwards;` | `animation: pulse-glow ...;` ✅ |
| `.text-deep` | `animation: focus-deep 0.8s ease-out forwards;` | (supprimée) ✅ |

Les animations d'apparition (fade-in + déblur) sont maintenant gérées **uniquement par framer-motion** dans le composant React, sans interférence CSS. L'animation `pulse-glow` bioluminescente reste active sur les titres pour l'effet de glow continu.

Tu peux relancer ton serveur Next.js et vérifier que le texte du Hero s'affiche correctement ! 🚀
La solution : retirer `focus-deep 1.2s ease-out forwards` de `.title-bio` et `focus-deep 0.8s ease-out forwards` de `.text-deep`, laissant framer-motion gérer exclusivement les animations d'apparition.
