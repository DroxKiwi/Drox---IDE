## Pourquoi Drox

Les agents dans l’éditeur sont devenus indispensables — mais trop souvent derrière un compte, un cloud et des règles de plateforme.

**Drox**, c’est l’inverse : un moteur agent **open source**, **local**, que tu contrôles. Même confort d’un agent qui lit, planifie et modifie le code — sans dépendre d’une société pour le cœur du système.

Enjeu technique : faire tenir une boucle agent sérieuse (LLM, outils, permissions, sessions) dans du **Rust** embarquable, branchable sur **ton** Ollama ou ton endpoint — pas sur le nôtre.

## Indépendance

- Données et sessions **sur ta machine** (`.drox/`, profil IDE local).
- LLM **que tu choisis** — local ou API que **tu** configures.
- Code **lisible, forkable, auditable** (MIT).
- Objectif : retrouver un confort d’agent **sans céder la pile** à un vendeur.
